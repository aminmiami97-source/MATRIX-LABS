# MATRIX LABS V0.4 — MATRIX Network Setup

## Architecture

V0.4 uses a hosted Supabase project for email/password accounts, Postgres credit balances, and an authenticated Edge Function. The Windows app contains only the public Supabase project URL and publishable/anon key. These values identify the project; they do not authorize privileged database access when Row Level Security is configured.

The shared model-routing key is a server-side secret named `MATRIX_AI_ROUTER_KEY`. It is read only by the `matrix-chat` Edge Function. Never place it in React, Rust, a GitHub file, a GitHub Actions build variable, or the Windows installer.

## Account and credit rules

- New Supabase Auth accounts receive one 300 CRD welcome grant from a Postgres trigger.
- The grant is stored in `credit_ledger` and is not generated by the desktop UI.
- Email verification is required before the chat function accepts requests.
- Each successful assistant response costs 1 CRD.
- A credit is reserved before sending the model request and refunded if the upstream request fails.
- The client can read its own balance but cannot insert ledger rows or update the balance.
- Agent profiles and chat transcripts are saved locally in per-user storage in this preview; they are not yet synchronized between devices.

The current application-level free-model safeguards are 10 requests per user per rolling 24 hours and 4 per minute, plus shared limits of 45 requests per rolling 24 hours and 15 per minute. The upstream free-model service can apply additional limits. A 300 CRD balance does not promise 300 requests per day.

## Models

The server accepts exactly these two model IDs:

- **AGOORA 2.0** — `liquid/lfm-2.5-2.6b:free`
- **MATRIX AI 1.0** — `thinkingmachines/inkling-small:free`

The `:free` variants are currently listed at zero model-token price. Availability and service-level limits can change. Liquid's model listing notes prompts and outputs may be retained and used to train Liquid models. Users should not send passwords, secrets, or sensitive personal information.

## Set up the hosted project

A responsible project administrator should own the hosted database and provider credentials. Do not publish shared secrets or ask users to paste keys into MATRIX LABS.

1. Create a Supabase project for MATRIX LABS.
2. In the Supabase Authentication settings, enable email confirmation for new accounts.
3. Open the Supabase SQL Editor and run the migration at `supabase/migrations/202610300001_matrix_network.sql`, or use the Supabase CLI migration workflow.
4. Deploy the Edge Function `matrix-chat` from `supabase/functions/matrix-chat/index.ts`.
5. In Supabase Dashboard → Edge Function Secrets, add `MATRIX_AI_ROUTER_KEY` with a newly created, unexposed server key.
6. Add the project URL and publishable/anon key as GitHub repository Actions secrets:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
7. Run the Windows installer workflow. The build embeds only the public project connection settings.

Never reuse a key that was pasted into a chat, screenshot, issue, or source file. Revoke exposed keys and replace them in the server secret store. Do not paste replacement keys into ChatGPT or GitHub.

## CLI deployment outline

From the repository root, with the Supabase CLI installed and the project administrator authenticated:

    supabase login
    supabase link --project-ref YOUR_PROJECT_REF
    supabase db push
    supabase functions deploy matrix-chat

Set the provider key in the Supabase Dashboard's Edge Function Secrets interface. Do not put the key in a shell command, source file, or repository.

## GitHub Actions configuration

In the repository Settings → Secrets and variables → Actions, add the two public build configuration values named above. They are used only when Vite builds the app.

The backend's `MATRIX_AI_ROUTER_KEY` is not a GitHub Actions secret and is not needed by the Windows build. It belongs in Supabase Edge Function Secrets only.

## Data flow

When a signed-in user sends a message, the desktop app sends the selected model ID, agent instructions, recent chat messages, and a one-time request ID to the authenticated `matrix-chat` Edge Function. The function validates the account and model allowlist, reserves one credit, and sends a chat-only request to the model service. It does not provide tools or computer-control functions. The shared API key never leaves the backend.

The model service receives the user's prompt and conversation. Its own privacy and retention policies apply. The app does not send files, email, screenshots, or other Windows content in V0.4.

## Troubleshooting

- **Backend setup screen:** Add the public Supabase URL and publishable/anon key as GitHub Actions secrets, then rebuild.
- **Email not verified:** Complete the confirmation link before signing in.
- **Credit account not ready:** Confirm the SQL migration and auth user trigger are installed.
- **MATRIX AI not configured:** Check that `MATRIX_AI_ROUTER_KEY` exists in Supabase Edge Function Secrets.
- **Model or quota error:** Confirm the exact allowlisted model ID and retry later. Free model service limits are outside the desktop app's control.
- **No chat access:** Review the Edge Function logs and the user's Supabase Auth session.
